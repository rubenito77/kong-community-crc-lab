## Objetivo y alcance

La prueba aplicó `cors` únicamente al Ingress `kong-transform-echo`, publicado
en `/transform`. Las rutas `/demo` y `/demo2` se conservaron como controles sin
el plugin.

```text
/transform -> KongPlugin demo-cors -> kong-transform-echo
/demo      -> sin CORS
/demo2     -> sin CORS
```

## Primer PipelineRun y corrección

El primer intento, `kong-plugin-cors-kqs4s`, aplicó correctamente el plugin,
pero la Task `test-cors` falló:

```text
allowed preflight status=200
```

La Pipeline esperaba exclusivamente `204`. La observación manual confirmó que
Kong Community 3.9.3 respondió `200` con cuerpo vacío y todos los headers CORS
correctos. La validación se corrigió para aceptar `200` o `204`, manteniendo
estrictas las comprobaciones de headers.

## Preflight permitido

Solicitud:

```text
OPTIONS /transform
Origin: https://cliente-lab.example
Access-Control-Request-Method: GET
Access-Control-Request-Headers: X-Lab-Client
```

Respuesta observada:

```text
HTTP/1.1 200 OK
vary: Origin
access-control-allow-origin: https://cliente-lab.example
access-control-allow-headers: Accept,Content-Type,X-Lab-Client
access-control-allow-methods: GET,OPTIONS
access-control-max-age: 600
content-length: 0
server: kong/3.9.3
```

## GET permitido

El GET con el origen autorizado respondió:

```text
HTTP/1.1 200 OK
access-control-allow-origin: https://cliente-lab.example
access-control-expose-headers: X-Lab-CORS
```

## Origen no autorizado

La solicitud envió:

```text
Origin: https://origen-no-permitido.example
```

Kong no reflejó ese origen ni devolvió `*`; mantuvo:

```text
access-control-allow-origin: https://cliente-lab.example
```

Aunque la respuesta HTTP del upstream es `200`, un navegador compara el
`Origin` solicitado con `Access-Control-Allow-Origin`. Como no coinciden, no
entrega la respuesta a JavaScript. CORS no es autenticación ni un bloqueo HTTP
del servidor: es una política aplicada por el navegador.

## Rollback

```powershell
oc annotate ingress kong-transform-echo -n kong-demo konghq.com/plugins-
oc delete kongplugin demo-cors -n kong-demo
```

Después del rollback, `/transform`, `/demo` y `/demo2` deben continuar en HTTP
200, sin headers CORS del laboratorio.
